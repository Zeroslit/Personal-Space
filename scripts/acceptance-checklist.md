# 验收清单

> [English version](acceptance-checklist.en.md) · 中文版

## 前置

1. 构建：`./scripts/build.sh`（Windows：`./scripts/build.ps1`）→ 产出 `server/target/personal-space.jar`
2. 启动：`java -jar server/target/personal-space.jar`，打开 <http://127.0.0.1:8787>
3. 自动化自测：
   - `./scripts/smoke-test.sh`（或 `smoke-test.ps1`）→ 应全部 PASS
   - `cd web && npm test` → 37 个用例通过（表单校验 16 + 搜索筛选 13 + 演示内嵌判定 8）

## 一、链接规则（本轮重点）

| # | 验收点 | 怎么验 | 期望 |
| --- | --- | --- | --- |
| 1 | GitHub 仓库必填 | 新建项目只填标题 | 提交被拦，仓库字段下方提示「GitHub 仓库地址必填」 |
| 2 | 只填仓库 | 只填 `repoUrl` | 保存成功；卡片只有「仓库」入口，不出现「立即预览」 |
| 3 | 仓库 + 演示 | 两个都填 | 保存成功；「仓库」「立即预览」两个入口都在 |
| 4 | 缺仓库只有演示 | 只填 `siteUrl` 不填仓库 | 同样被拦（演示网址不能替代仓库地址） |
| 5 | 协议非法 | 填 `ftp://example.com` 或 `example.com` | 提示必须以 `http://` / `https://` 开头且含主机名 |
| 6 | 后端同规则 | `curl -X POST .../api/projects -d '{"title":"x"}'` | 400 + `{"error":"validation_error","message":"repoUrl（GitHub 仓库） 不能为空"}` |
| 7 | 编辑时清空 | 编辑已有项目，把仓库地址清空后保存 | 同样被拦（`PUT` 走同一套校验） |

## 一之二、GitHub 简介自动填充与直接跳转（本轮新增）

| # | 验收点 | 怎么验 | 期望 |
| --- | --- | --- | --- |
| 47 | 自动带出简介 | 新建项目，在「GitHub 仓库」里粘贴一个公开仓库地址（如 `https://github.com/openai/openai-python`） | 简介框自动填入该仓库的 description，摘要框上方出现「GitHub 上的简介」建议卡 |
| 48 | 不覆盖手写内容 | 先手写简介，再改仓库地址 | 已写的简介不被覆盖，只在建议卡里给出 GitHub 的简介 |
| 49 | Enter 采用 / Shift+Enter 换行 | 光标在简介输入框内按 `Enter`；再按 `Shift+Enter` | `Enter` 采用建议并弹带「撤销」的 Toast；`Shift+Enter` 只是换行 |
| 50 | 读不到也只提示 | 填一个不存在的仓库（`https://github.com/example/nope-nope-nope`） | 提示「没读到 GitHub 简介…」，手写与保存都不受影响 |
| 51 | 代取接口 | `curl "http://127.0.0.1:8787/api/github/repo?url=https%3A%2F%2Fgithub.com%2Fopenai%2Fopenai-python"` | 200 + `summarySuggestion`；非 github.com → 400，缺 `url` → 400，仓库不存在 → 404 |
| 52 | 登录站点直接跳转 | 给项目填演示网址 `https://github.com/login`（或勾选「演示页需要登录」） | 卡片按钮变成「打开演示」、直接新标签跳转；详情页显示封面占位 + 原因，不出现视口切换与刷新 |
| 53 | 禁止内嵌的站点 | 演示地址填 `https://accounts.google.com/signin` | 同上：不尝试内嵌，给出「打开 accounts.google.com」按钮；点「仍然内嵌试试」才会真的内嵌 |
| 60 | 仓库没写描述 | 粘贴一个 GitHub 上没有 description、但有 README 的仓库（例如 `https://github.com/Zeroslit/University-Book-Trading-Market`） | 自动带出 README 首段，建议卡上写「GitHub README 的第一段」；接口响应里 `summarySource` 为 `readme` |
| 61 | 描述和 README 都拿不到 | 粘贴一个既没写 description、README 也没有正文的仓库 | 摘要框下方提示「这个仓库在 GitHub 上没写描述…简介只能自己写了」，不会毫无反应 |
| 62 | 关掉再打开不残留 | 在「新建项目」里粘一个 GitHub 地址、等简介自动带出，关掉弹窗，再点一次「新建项目」 | 标题、简介、标签都是空的：上一轮自动填进去的简介不会跟过来 |
| 63 | 手动清空不回填 | 简介被自动填上后，把简介删空 | 保持为空，不会又把建议塞回来；想用建议按 Enter 或点「使用」 |

## 九、点击跳转

| # | 验收点 | 怎么验 | 期望 |
| --- | --- | --- | --- |
| 54 | 卡片整卡点击 | 点卡片封面或简介的空白处 | 进入该项目的详情页 |
| 55 | 卡片内按钮不误触 | 点卡片上的「立即预览」「编辑」「拖拽手柄」 | 只触发按钮本身，不会顺带跳详情 |
| 56 | 列表 / 时间线视图 | 点这两个视图里的任意一行空白处 | 同样进入详情页 |
| 57 | 外链直达 | 点「仓库」/「打开演示」按钮 | 新标签打开目标站点（`rel="noreferrer noopener"`） |
| 58 | 粘贴后直接回车 | 粘贴 GitHub 地址后光标留在仓库输入框，按 `Enter` | 采用自动带出的简介（与 #49 等价）；若简介已被自己改写过则什么都不做，绝不覆盖手写文案 |
